# iOS Unity Integration

This package does not ship Unity build output. Host applications must provide a
Unity iOS export and embed `UnityFramework.framework` in the native iOS app.

## Current Status

The iOS bridge uses the Expo Modules API and loads Unity dynamically:

- The package compiles without Unity headers or `UnityFramework.framework` in
  the npm package.
- If `UnityFramework.framework` is embedded in the host app at runtime, the
  bridge can load it, start Unity embedded in the app, resolve Unity's root
  view, and attach that view to `UnityShowView`.
- If Unity is not available, commands reject with a coded runtime error and view
  rendering emits an error event.

This keeps npm package size reasonable and avoids publishing generated Unity
artifacts.

## Unity Export Contract

Use Unity's iOS export with Unity as a Library. Unity's generated Xcode project
contains:

- `UnityFramework`: the reusable framework target that contains Unity runtime,
  player code, plug-ins, and generated Unity sources.
- `Unity-iPhone`: a thin launcher app target that should be replaced by the
  React Native / Expo application.

The host app must build and embed the generated `UnityFramework.framework` in
the app target. For Expo CNG apps, use the config plugin documented in
[`EXPO_CONFIG_PLUGIN.md`](EXPO_CONFIG_PLUGIN.md).

Recommended local layout for the example app:

```text
example/
  unity/
    ios/
      Unity-iPhone.xcodeproj
      UnityFramework.framework
```

`example/unity/` is ignored by Git.

## JavaScript to Unity

`sendMessage()` maps to Unity's iOS framework API:

```ts
await sendMessage({
  gameObject: 'Bridge',
  methodName: 'ReceiveMessage',
  payload: {
    score: 21,
  },
});
```

The iOS bridge calls:

```text
UnityFramework.sendMessageToGOWithName(gameObject, functionName, payloadString)
```

String payloads are forwarded as-is. Object and array payloads are serialized to
JSON.

## Unity to JavaScript

Unity C# code can emit events through C symbols exported by the iOS bridge:

```csharp
using System.Runtime.InteropServices;
using UnityEngine;

public class ReactNativeBridge : MonoBehaviour
{
    [DllImport("__Internal")]
    private static extern void UnityShowEmitReady(string unityVersion);

    [DllImport("__Internal")]
    private static extern void UnityShowEmitMessage(string name, string jsonPayload);

    [DllImport("__Internal")]
    private static extern void UnityShowEmitStateChange(string state, string reason);

    [DllImport("__Internal")]
    private static extern void UnityShowEmitError(string code, string message, bool recoverable);

    public void EmitReady()
    {
        UnityShowEmitReady(Application.unityVersion);
    }

    public void EmitMessage(string name, string jsonPayload)
    {
        UnityShowEmitMessage(name, jsonPayload);
    }

    public void EmitError(string code, string message)
    {
        UnityShowEmitError(code, message, true);
    }
}
```

JavaScript receives these via:

```ts
const subscription = addUnityEventListener('message', (event) => {
  console.log(event.name, event.payload);
});
```

## Lifecycle

The iOS module exposes:

- `loadUnity(source?)`
- `pauseUnity()`
- `resumeUnity()`
- `unloadUnity()`

The Expo module also forwards app background/foreground/destroy events to the
Unity runtime when Unity has been loaded.

## Unity Limitations

Unity as a Library has important iOS constraints:

- Unity rendering is designed for full-screen use and does not officially
  support rendering on only part of the screen.
- Only one Unity runtime instance can be loaded in a process.
- Third-party native or managed Unity plugins may need adaptation.
- `quitApplication` fully unloads Unity; after this call Unity cannot run again
  in the same process.
- Unity recommends calling `setExecuteHeader` before running Unity so its crash
  reporter works correctly. The current bridge loads Unity dynamically and does
  not yet install that execute header automatically.
- The Swift Xcode project type generated by Unity does not support Unity as a
  Library; use Unity's Objective-C iOS export.

The React Native view contract exists for ergonomic composition, but product
integrations should treat Unity as a single full-screen/native surface unless a
specific Unity version and project setup proves a narrower embedded layout is
supported.
